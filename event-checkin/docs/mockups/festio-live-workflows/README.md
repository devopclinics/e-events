# Festio Live Experience Workflow Concept Mockups

These images are pre-implementation design inputs for the staging workflow project. They are not screenshots of working Festio code and must not be used as readiness evidence.

## Boards

- `mbf-scenes-01-05.png` — Opening, Happiness Poll, Results, Twenty Years, Harvard Video
- `mbf-scenes-06-10.png` — Islamic Perspective, Connection Framework, Connection Test, Connection Challenge, Community Check
- `mbf-scenes-11-15.png` — Next 20 Years, Word Cloud, Happiness After, Before/After, Closing
- `workflow-product-surfaces.png` — Experiences list, Builder, Presenter Console and mobile participant states

## Approved direction represented

- cinematic large-screen presentation rather than dashboard cards;
- coherent midnight/teal/gold/vibrant accent family;
- one idea per TV scene;
- ranked results instead of cramped legends;
- practical presenter controls separate from TV output;
- mobile participation designed independently from TV;
- generic Builder and Experiences library around MBF configuration;
- real before/after denominators and percentage-point labeling in the proposed implementation.

## Review cautions

- Generated Arabic and religious-source typography is conceptual only. Production content requires exact configured source text, an Arabic-capable font, explicit RTL layout tests and knowledgeable human review.
- People/media shown in conceptual frames are placeholders. Production Harvard media requires an approved source and usage rights.
- Percentages and response totals in mockups are sample preview data. The live implementation must use actual persisted analytics.
- Emoji-like or generated pictograms are visual placeholders. Production should use Festio's consistent vector icon system.
- Builder Preview, Presenter Preview and Live Display must share the same production renderer; these static images do not satisfy that requirement.

## Implementation proof required later

The project plan requires actual staging screenshots of all scenes and product surfaces, responsive and accessibility evidence, reload/reconnect tests, a second unrelated Technology Conference workflow, and regression/failure-isolation results before any readiness decision.
