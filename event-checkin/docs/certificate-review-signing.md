# Certificate design review and signatory collection

Open **Design Studio → Certificates** for the selected event. The same workspace is available wherever Festio shows participant certificates.

1. In **Start with a design**, add a reusable style. Royal Purple, Heritage Gold, Midnight Copper and Ivory Signature are event-independent presets. Set the wording, colours, logo and eligibility rules above, then **Save design and rules**.
2. Under **Client review**, select the saved templates and create a review link. Share it with the client. Their name, chosen template and optional note are recorded in Festio. Refresh responses to see the choice. The shared proof is an immutable snapshot: later template changes require a fresh review. A client choice does not issue certificates or automatically change the event's template.
3. Open the agreed template. Under **Signatories**, select the first or second signature slot, enter the role/request label, optionally specify the intended email, and create a private signing link. Send each link directly to its intended signatory. Links are displayed once; generating a replacement for the same slot revokes the earlier request and approval.
4. The signatory opens the link without a Festio account, reviews the sample, supplies their full name and title, draws a signature, and explicitly authorises its use for this event and saved design. A valid submission is single-use. The email field is a match check, not email-ownership verification; possession of the private link is not independent identity verification.
5. Refresh the organiser workspace. Inspect each name, title and signature and choose **Approve for certificates**. Every configured signature slot must have approval for the current saved design. Pending, revoked or outdated requests block manual issuance and cause automatic issuance to wait. Replacing a request requires fresh submission and approval.
6. Check participant eligibility and issue certificates using the existing controls. **Issue selected** does not email them; **Issue & email** explicitly requests delivery. No certificate or email is created by sharing, choosing a design, signing or approving a signature.

Review links last 14 days; signing links last 7 days (API supports 1–30 days). Revocation takes effect on subsequent access. Approvals collected before expiry remain usable for their exact saved design. An already issued certificate retains its participant name, design and approved-signature snapshot. Later design edits, request revocation or new signatures do not rewrite it. Use the existing certificate revocation action to withdraw an issued credential.

Tokens are generated randomly and stored as SHA-256 hashes. Public proofs omit private signature images, signatory email addresses and guest records. Collected signatures stay in the event's protected workflow records until explicitly approved; approved signature images are intentionally included on issued participant certificates and their verification pages. Do not share signatory links publicly.

Existing templates without signature requests retain their previous issuance behaviour. Preset installation does not enable automatic issuance. This feature adds the `certificate_workflow_links` table through the existing metadata migration; no existing guest, admission, seating or messaging settings are modified.

The four original compositions are saved as `layout_version: 2`. Their masthead, frame, theme panel, seal and paired signature areas come from the original design files. Studio uses a server-rendered preview, and client review, signing proofs and PDF export use the same renderer. Branding, theme and seal fields are editable under **Branding, theme and seal**. Opening an existing preset with **Add / open style** upgrades that saved preset; this changes its reviewed design and requires fresh review/signature approval. Issued version-1 snapshots retain their earlier rendering.
